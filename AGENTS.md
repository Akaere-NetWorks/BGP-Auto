# AGENTS.md

Guidance for agentic coding assistants working in this repo.

## Repository overview
- Purpose: generate BGP route filter configs from TOML input files using `bgpq4`.
- Language: Python.
- Entry point: `src/main.py`.
- Inputs: `config/*.toml`.
- Outputs (generated): `output/`, `html/`, `logs/`.

## Setup
- Python dependencies: `pip install -r requirements.txt`.
- External dependency: `bgpq4` must be installed and on PATH.
  - Ubuntu/Debian: `sudo apt install bgpq4`
  - macOS: `brew install bgpq4`

## Common commands
- Run the app from repo root:
  - `python src/main.py`
  - Alternative (as in README): `cd src && python main.py`
- Clean generated artifacts (if needed): remove `output/`, `html/`, `logs/`.

## Code style guidelines

### Imports
- Use standard library imports first, then third-party, then local modules.
- Keep one import per line.
- Prefer `from pathlib import Path` for path operations.
- Example order (observed):
  - stdlib: `import sys`, `import subprocess`, `from pathlib import Path`
  - third-party: `import tomli`
  - local: `from config_parser import ConfigParser`

### Formatting
- Indentation: 4 spaces.
- Line length: keep reasonable; avoid very long lines unless HTML templates require it.
- Use f-strings for interpolation.
- Use explicit encoding for HTML file writes (`encoding='utf-8'`).

### Types and signatures
- Type hints are used for public methods and return values where helpful.
- Use `Optional[...]` for nullable returns.
- Prefer concrete types like `List[Path]`, `Dict[str, List[Dict]]`.
- Keep signatures simple and explicit; default parameters used sparingly.

### Naming conventions
- Modules: `snake_case.py`.
- Classes: `CamelCase`.
- Functions/methods/vars: `snake_case`.
- Constants: `UPPER_SNAKE_CASE` if added.

### Error handling and logging
- Use `try/except` around I/O and subprocess calls.
- Prefer logging via `Logger` (see `src/logger.py`) when available.
- On recoverable issues, log warning and continue.
- On critical issues, log error and return/exit early.

### File I/O
- Use `Path` objects for building file paths.
- Create directories with `mkdir(parents=True, exist_ok=True)`.
- Read/write text files with explicit encoding when output is HTML or user-visible.
- Ensure merged outputs end with newline.

### Subprocess usage
- Use `subprocess.run([...], capture_output=True, text=True, check=True)`.
- Log command execution when possible.
- Handle `CalledProcessError` and `FileNotFoundError` explicitly.

### Data handling patterns
- Config parsing returns dicts with keys: `name`, `ipv6`, `from`.
- Use lists of dicts for sections and diff records.
- Sorting: routes are sorted before display/output.

### HTML generation
- HTML is generated via Python string templates.
- Keep inline CSS simple and consistent.
- Use `utf-8` when writing HTML files.

### Git/diff behavior
- Diff generation relies on `git` history; failures should not crash the run.
- Local uncommitted changes are compared to `HEAD` when possible.
